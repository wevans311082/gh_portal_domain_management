# Shared DNS provider switching

Required by the user on 30 October 2026 and added to roadmap item 5. Signup, customer and admin controls must launch one shared workflow for Cloudflare or WHM/platform DNS, including provider configuration and ResellerClub delegation updates. This feature is **in progress**, not enabled or accepted.

## Verified provider transport foundation

Cloudflare transport now bounds connection/read time to 10/30 seconds, disables redirects and performs one HTTP call per invocation. Transport/JSON errors and provider bodies are not exposed in exceptions. Mutation transport failures, redirects, server errors and unrecognized success envelopes retain uncertainty for the future operation reconciler. A successful envelope requires an actual boolean `success=true`; it is not by itself proof of completed DNS configuration or delegation. HTTP rejection classification is transport information, not authorization to replay a provider mutation.

`list_zones` accepts a validated domain and explicit 32-character account identifier, with exact name/account filters, match-all semantics and bounded page size/page input. `create_zone` can retain the selected account in its request and defaults discovery off. The old unscoped create signature remains compatible for the existing registration path; the new switching workflow must require an explicit captured account. No provider lookup or creation was performed against a live account during development.

Fifteen new transport checks cover scoped lookup/create requests, timeout/redirect bounds, no automatic mutation replay, sanitized timeout errors, HTTP rejection/uncertainty, malformed success envelopes and input rejection before HTTP. The combined transport/DNS CRUD/platform-cache run passes **39 checks**. Django and whitespace checks pass. The final full application suite passes **2,631 tests**, with the unchanged deployment assertion deselected.

The first full run found four old transport fixtures without real HTTP status values and an expectation that raw HTTP errors escape. Those fixtures now supply real status codes and verify the sanitized Cloudflare exception contract. The transport plus existing services/middleware suite passes **32 checks**; the final full rerun passes as recorded above. Account configuration UI, durable scopes/jobs and switch controls are not implemented by this transport increment.

Cloudflare documents account-scoped zone creation and notes that a new zone starts pending until the delegation/verification step is completed. This confirms that zone creation cannot be the final success state. See [Create Zone](https://developers.cloudflare.com/api/resources/zones/methods/create/). The lookup filters and pagination follow [List Zones](https://developers.cloudflare.com/api/resources/zones/methods/list/).

The WHM stage must operate on the domain's DNS zone and the platform/reseller nameserver configuration. cPanel distinguishes those settings from individual account nameservers; the legacy `modifyacct` helper is not evidence that a DNS-zone migration completed. See [cPanel nameserver setup](https://docs.cpanel.net/knowledge-base/dns/how-to-set-up-nameservers-in-a-cpanel-environment/) and [WHM DNS record API guidance](https://support.cpanel.net/hc/en-us/articles/1500000323641-How-to-add-a-DNS-record-to-a-domain-using-the-WHM-API).

## Captured account readiness and scope

`CloudflareService` now captures `CLOUDFLARE_ACCOUNT_ID` alongside its token. The account setting is available through the application environment/DB-first runtime settings and the validated portable-setting schema; it requires a 32-character hexadecimal value when supplied and is not a secret. An unset account remains compatible with old unrelated client paths, but cannot authorize a new switching job. No operator configuration was changed during implementation.

`cloudflare_integration.scope.provider_scope` checks the captured endpoint, account, token and actual authorization headers without an HTTP call or rereading configuration. It produces an application-keyed SHA-256 HMAC over that configuration. The retained value contains no credential text. The comparison helper rejects missing/unrecognized fingerprints, a changed account or credential, endpoint drift and conflicting header authority (including differently cased shadow authorization headers). Credential or application-key rotation requires review of an old request rather than silently using replacement authority.

Fifteen scope/schema regressions pass. The earlier combined scope/transport/services run passed 45 checks before the final shadow-header and endpoint cases were added; the final focused scope run passes all 15. Django and whitespace checks pass. The full application suite passes **2,646 tests**, with the unchanged deployment assertion deselected. These helpers are groundwork: they do not verify remote permissions, adopt a zone, create a job or change a domain's provider. The switching admission/worker must capture and recheck the scope at every external stage before those behaviors can be accepted.

## Read-only zone discovery and observations

`cloudflare_integration.zones` now provides exact scoped zone lookup and direct zone observation. It checks the captured configuration before and after each read, requires a matching account/domain and full-zone type, and validates every assigned nameserver against the shared registry workstream. Observations are immutable and retain only the zone identifier, normalized name/delegation, known preparation status, explicit paused flag and captured scope. Extra provider fields and diagnostic payloads are discarded. A pending/initializing observation is preparation evidence, not activation or registrar completion; a paused flag is retained rather than silently changed.

Lookup reads all reported pages within a five-page review limit before returning absence. Missing or inconsistent pagination, changing page counts/page sizes, duplicate matches, wrong-scope results and incomplete delegation require review. Direct observation must also match the requested zone identifier. The API's unfiltered `total_count` is not used to infer the filtered result count. These response fields follow [Cloudflare List Zones](https://developers.cloudflare.com/api/resources/zones/methods/list/); unusually large or unrecognized response contracts remain held rather than being treated as no zone.

Twenty-one new regressions pass, covering full 13-host observations, list/detail preparation versus active state, complete multi-page absence without creation, account/domain/type/status/identifier mismatches, malformed delegation, pagination drift, duplicate matches and scope rotation during a read. The combined zone/scope/transport run passes **51 checks**. Django and whitespace checks pass. The full application suite passes **2,667 tests**, with the unchanged deployment assertion deselected. These helpers perform no zone creation, adoption write, record mutation, reservation release or local DNS-provider change. Absence is a read observation, not permission to create; durable admission must still validate customer/admin authority, registry eligibility and the reviewed record plan before any mutation.

## Durable preview, confirmation and domain reservation

Migration `domains.0038_dns_switch_requests` adds retained DNS provider requests and a unique per-domain DNS reservation. The request preserves its UUID, customer, initiating actor, target provider, captured backend scope, registrar/source association, shared registry policy and cached DNS records. Preview/confirmation history cannot be rewritten through model saves. Once set, provider submission markers and zone associations cannot be reset through those saves. These checks supplement service-level manifests; they do not protect against unrestricted database modification.

`domains.dns_changes` now admits ordinary active customers for their own active domains and active platform owners acting on a customer domain. It locks customer then domain, requires a reviewed current registrar association, audits previews atomically and returns the original intact request on an exact key replay. Both Cloudflare and WHM targets have captured configuration fingerprints; the WHM fingerprint includes the endpoint, username, credential, TLS verification and actual authorization header. No credential is stored in the request. Existing bulk or contact work prevents admission.

Explicit confirmation rechecks the immutable manifest, expiry, actor authority, current source/cache and backend configuration under the same locks. It creates the domain reservation and audit atomically, then retains an `inventory` stage. Exact confirmed replay does not reset or repeat work. The shared local-edit and registrar-review guards recognize DNS reservations, so they block bulk/standalone-contact admission and existing guarded local/inventory/admin edits. There is no automatic reservation expiry or release based on a status label.

Cached records are explicitly marked **not remotely verified**. They do not authorize DNS migration or delegation. The next stage must obtain complete live inventory and a reviewed record plan before any provider mutation. This increment does not publish jobs, create/adopt zones, change `dns_provider`, update nameservers, charge customers or expose new HTTP routes. Legacy DNS CRUD/provisioning concurrency and already-running external operations still need integration before switching is enabled; the new reservation alone does not solve those paths.

Eighteen new regressions cover private durable preview/replay, confirmation and slot retention, changed source/provider rejection, cross-customer denial, bulk/contact conflict checks, manifest tampering, typed confirmation, preview/confirmation audit rollback, expiry, owner-assisted requests, changed MX records, both provider targets and retained submission-marker/zone identity. The combined DNS/bulk/inventory admission run passes **44 checks**. The isolated upgrade verifier passes through 0038, preserving historical domain/order/uncertain-item data and creating no inferred DNS requests or reservations. ## Complete Cloudflare DNS inventory reads

`cloudflare_integration.inventory.read_inventory` now obtains a scoped zone observation, reads every DNS-record page within a 1,000-record/five-page review bound, and rechecks the zone afterwards. It checks the captured credential/account before and after every HTTP read. Result counts, page totals, page sizes and the unfiltered total must agree; identifiers may not repeat across pages. Missing/inconsistent/oversized inventories require review, never truncation or a fabricated empty zone. The client retains its old unpaged call signature for existing CRUD while exposing validated explicit pagination for switching.

Every record is retained as bounded canonical JSON, including provider-specific/structured fields, comments and tags. MX priority, SRV data, automatic TTL and proxy flags are retained rather than converted to local-model defaults. Types not represented by the current local DNS model are explicitly flagged for migration review rather than discarded. The immutable inventory includes a stable, ordering-independent digest and its scoped zone observation. Wrong-zone names/identifiers, malformed data, duplicate identifiers or changed zone evidence invalidate the whole read.

Seventeen new regressions cover complete pagination, mail/structured/unfamiliar records, deterministic hashing, malformed/wrong-zone rows, duplicate IDs, missing/inconsistent totals, changed zone evidence and validated HTTP pagination parameters. The combined inventory/zone/transport run passes **53 checks**. Django and whitespace checks pass. The full application suite passes **2,702 tests**, with the unchanged deployment assertion deselected. Response pagination and fields follow [Cloudflare List DNS Records](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/list/).

This is a provider read snapshot, not a remote transactional lock, approved migration plan or completed switch. Source-account/authoritative-delegation bindings, record-version rechecks before applying changes, DNSSEC handling, proxy feature impacts and unsupported-record decisions remain required worker/review gates. A zone observation from a pending Cloudflare zone does not establish that it is serving the domain's live authoritative DNS. WHM and registrar/custom-source inventory integration and durable observation receipts/worker leases are still required. No provider records, zones or delegation were changed.

## Leased source inventory execution

Migration `domains.0039_dns_inventory_receipts` adds a durable inventory receipt/digest/time, observation token/lease and bounded progress message. `domains.dns_inventory.collect_dns_inventory` now claims confirmed requests under customer/domain/request locks, retains a ten-minute read lease and audits the claim before external reads. It refuses an enclosing business transaction. Live reads occur after commit, outside database locks; results commit only under the same unexpired token after fresh authorization, reservation, manifest, source/cache and backend-scope checks.

The implemented adapter reads an existing Cloudflare source for a Cloudflare or WHM target. Two ResellerClub association/delegation observations bracket the Cloudflare inventory. Both must match each other and the active Cloudflare zone's complete assigned nameservers. The receipt retains raw record snapshots, scoped zone evidence, record digest, unsupported-type flags and the observed registrar delegation, then enters `plan_review`. It does not approve a record plan, modify a provider or release the domain. Exact completed-stage replay makes no additional reads. A live lease suppresses duplicate claims; a superseded/expired observer cannot publish its result.

Preview/confirmation now capture both managed source and target DNS account scopes. Requests that no longer match the current source/configuration require a new review; old requests lacking that new source binding are not silently upgraded. Trusted internal hold exemptions are allowed only after the inventory service verifies its own reservation. Customer/admin routes still receive the ordinary holds and cannot supply an exemption through a new endpoint.

Failed verification retains the reservation and a sanitized review result. Audit-start failure prevents reads and rolls back the lease; final-audit failure rolls back evidence and retains the prior claim. Recorded receipts cannot be rewritten through model saves, and receipt-digest tampering is refused on replay. Eleven new integration checks cover receipt persistence/replay, matching authority, duplicate/stale leases, source/configuration changes, actor revocation and audit rollback; the combined inventory-stage/admission run passes **29 checks**. All mocked provider reads assert that no database transaction is open. The isolated sequential migration verifier passes through 0039, preserving uncertain submission markers and inventing no inventory evidence or leases. Django/diff checks pass; global migration dry run retains only documented unrelated drift. The full application suite passes **2,713 tests**, with the unchanged deployment assertion deselected.

WHM, registrar and custom-source adapters remain required; an unsupported source is retained for review rather than guessed from cached records. ## WHM configured-zone source inventory

The shared inventory execution stage now supports a WHM/platform source for a Cloudflare target. It uses WHM API 1 `parse_dns_zone`, not the legacy best-effort `dump_zone` parser. The API's base64 owner/content fields are retained losslessly, including arbitrary non-UTF-8 bytes, multipart TXT/SRV data, comments and control lines. No line is silently dropped or converted through a replacement-character decoder. Unsupported record types and binary data remain flagged for migration review.

The read adapter requires one apex SOA, complete apex NS records matching the configured platform nameservers, valid typed metadata and bounded payloads. It preserves the zone serial and every parsed line, and reads twice to reject any change in the complete snapshot, even if an external edit fails to update the serial. Relative owners follow the documented zone-relative form. Unrelated absolute owners, duplicate line indexes, malformed base64, ambiguous authority and control statements such as external includes require review. This records a configured WHM zone bound to the request and matching registrar delegation; it does not replace final public DNS/DNSSEC/activation checks.

WHM request authority now includes the reviewed nameserver configuration as well as endpoint, username, credential and TLS/header state. Changing that configuration invalidates retained request scopes rather than silently using new delegation. Portable `WHM_NAMESERVERS` settings now support the same 13-host bound and sufficient length for full hostnames. Old WHM requests/scopes need renewed review rather than an inferred configuration upgrade.

The dedicated read transport uses bounded connection/read timeouts, refuses redirects, accepts only the documented typed success metadata and exposes no provider error body. cPanel's [parsed zone API](https://api.docs.cpanel.net/openapi/whm/operation/parse_dns_zone/) and [published WHM OpenAPI schema](https://api.docs.cpanel.net/_spec/specifications/whm.openapi.yaml) define this representation and warn that decoded data may be arbitrary bytes. No private WHM or registrar endpoint was contacted during development.

Nineteen new checks cover lossless binary/mail/SRV/comment/control retention, stable two-read evidence, malformed or unrelated payload rejection, configured-NS binding, safe HTTP transport and the shared leased WHM-to-Cloudflare source stage. The combined WHM inventory/shared stage/admission run passes **48 checks**, including assertions that provider reads occur outside database transactions and that the reservation remains held for plan review. Django and whitespace checks pass. The full application suite passes **2,732 tests**, with the unchanged deployment assertion deselected. Record-plan approval, provider provisioning/mutation, registrar/custom-source adapters, queue/control lifecycle and the signup/customer/admin switching interfaces remain required. No DNS mutation or delegation update was enabled.

## Retained source record plans and explicit approval

The shared backend now builds deterministic source migration plans in `domains.dns_record_plan` and retains revisions and approvals through `domains.dns_plan_review`. Migration `domains.0040_dns_record_plans` introduces immutable plan history and an explicit approved-plan reference; historical requests gain neither inferred plans nor approvals. Plan creation and approval are offline operations, with customer/domain/request locks, fresh actor authorization, reservation and backend-scope checks, a 30-minute inventory lifetime and atomic audit records. Exact replay preserves the original plan and approval attribution. A maximum of 20 retained revisions bounds each request.

Every input row remains visible, including WHM comments/control lines and duplicate answers. Pinned `dnspython==2.9.0` parses records and compares canonical DNS wire data, preserving TXT byte/chunk boundaries, MX priorities, SRV fields and CAA values. The parser performs no DNS resolution. See the [dnspython record parsing documentation](https://dnspython.readthedocs.io/en/latest/rdata-make.html). Unsupported types, DNSSEC records, ambiguous values, CNAME conflicts and incompatible TTLs block approval. Explicit per-record TTL revisions retain the original source data. Apex NS/SOA records are identified as target-managed authority rather than copied.

Cloudflare proxy removal, enabled record settings and retained-only tags/comments require explicit acknowledgements when moving to WHM. Unknown settings and private-routing records require separate review. Cloudflare target options remain in the plan. Automatic TTL is never silently translated into a WHM TTL; the actor must choose an explicit value. Cloudflare TTL bounds and record representation follow its [DNS records API](https://developers.cloudflare.com/api/resources/dns/subresources/records/).

The focused planner/approval/inventory suite passes **43 tests**. The full application suite passes **2,763 tests**, with the unchanged nginx deployment assertion deselected. The isolated upgrade verifier passes through 0040 and Django system, dependency consistency and whitespace checks pass. A targeted advisory scan reports no known vulnerabilities for the added DNS parser dependency. The global migration dry run reports only the previously documented unrelated model drift; those migrations were not generated or applied. These checks use isolated fixtures and do not establish live provider or browser acceptance for the switching workflow.

This approval covers the source migration plan only. It does not authorize record writes or delegation updates. Complete target inventory/conflict review, fresh source rechecks before mutation, DNSSEC handling, durable submission markers, provider verification and final public activation remain required. No new switching interface or execution job is enabled by this increment.

## Remaining required implementation

- Signup handoff integration and durable execution stages, verified record-plan bindings, per-stage mutation markers, reservation lifecycle and audit attribution beyond the initial switch admission.
- Provider readiness and exact zone adoption checks; complete DNS record pagination and migration planning, including mail records, unsupported records and DNSSEC requirements.
- Cloudflare zone provisioning/adoption and WHM zone provisioning through the correct DNS APIs, with known-completion verification and partial/uncertain result reconciliation.
- ResellerClub complete delegation submission/observation/terminal verification, sharing the existing reviewed registry workstreams and uncertain-operation fences.
- Replace temporary Cloudflare signup delegation and the legacy WHM account-nameserver helper. Retain both provider and registrar stage results; do not delete old zones when a control is switched off.
- Signup/customer/admin selection, preview, confirmation, progress, failure/review and selective retry interfaces, with authorization, CSRF, recent MFA where applicable and desktop/mobile accessibility checks.
- End-to-end acceptance for both switching directions, record preservation, stale-source/scope rejection, timeouts and exact replay. Real provider sandbox/runtime checks remain external gates; no sandbox is configured and production must not be used as a substitute.

The transport work does not satisfy those workflow or UI requirements. Existing DNS provider metadata fields are not being counted as functioning switches.
